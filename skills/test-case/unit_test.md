# 说明

本文档说明如何根据模块设计编写单元测试设计文档。

# 工作流

## Phase 1：设计测试 Case

根据模块设计编写单元测试 Case，并落地为 Markdown 文档。如果是对现有模块进行迭代，则基于现有的测试文档进行编辑修改。

详细说明每个 Case 的测试内容、测试流程以及预期结果。

需要包含所有会发生变动代码，包含目标模块及其连带影响的其他模块或者流程。

## Phase 2：Review 测试文档

启动一个 SubAgent，对模块的测试文档进行 Review，找出遗漏或问题。

根据 SubAgent 的反馈修正测试文档。

## Phase 3：用户 Review

等待用户完整 Review 测试文档，并根据用户意见进行修改。
